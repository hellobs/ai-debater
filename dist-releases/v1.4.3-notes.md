# v1.4.3 — 云端 DeepSeek 配置打通 · 前端覆盖后端 bug 修复

一句话：**把"用你已有的 DeepSeek 密钥跑云端"这条最想要的路径彻底打通**，并修掉一个会让前端开机把服务端已配好的上游冲掉的隐蔽 bug；顺带清掉一批文档/模板里把默认模型写成已下架 `deepseek-chat`、把桥写成需单起 `8011` 的旧口径。

---

## 为什么有这一版

两个痛点：

1. **云端配置进不去**：用户已有 DeepSeek 密钥，但默认模型还是已下架的 `deepseek-chat`（云端直接 400）、桥地址还写着需单起的 `8011`，前端下拉只列本机 Ollama——照着旧文档根本配不上云端。
2. **前端开机把后端冲掉**：`App.tsx` 启动时会把 `localStorage` 里的旧上游配置推给后端。一旦服务端已经配好云端上游，前端一加载就把内存里的配置覆盖成本机 Ollama——表现为"明明配好了，一刷新又变回本机"。

---

## 核心改动

### 1. 云端 DeepSeek 配置打通（用已有的密钥，零新增依赖）

- `ANTHROPIC_BASE_URL` 实测口径：`https://api.deepseek.com/anthropic`
  （`POST /anthropic/v1/messages` = 200；`/v1/messages` = 404；`GET /models` = 200；`/anthropic/v1/models` = 404）
- 默认模型 `deepseek-chat` → **`deepseek-flash`**（`deepseek-chat` 已下架，云端会 400；合法名只剩 `deepseek-flash` / `deepseek-v4-pro`）
- 协议桥是**挂载式**：mavis 走写死的 `127.0.0.1:8010/bridge/v1`，无需单起独立桥；`LLM_BRIDGE_URL` 仅 `ollama`/`openai` 直连形态才用
- 新增 `scripts/run_cloud.sh`（与 `run_local.sh` 对称）：一键起后端+前端，打印上游/模型/预算/密钥长度
- 上游状态显示改为取网关主机；模型清单按网关实情回退探测（`/anthropic` 不通就剥掉再试 `/models`）

### 2. 前端开机覆盖后端 bug 修复（隐蔽真 bug）

- 原 `App.tsx` mount effect：无条件把 `localStorage` 旧配置 `POST /api/upstream` 推给后端 → 把服务端内存里的云端上游洗回本机
- 改为**以服务端为准**：先 `GET /api/upstream`，`if (cur.upstream.base_url) return`——服务端已有配置就不再推
- 新增 2 条前端用例（服务端有配置时不 POST；服务端空时用本机），变异检验精准命中单点

### 3. 同步修掉 spike / bootstrap 同款 bug 复发

`spike_01/02/03`、`scripts/bootstrap.sh` 的桥地址 `8011` → `8010/bridge/v1`、模型 `deepseek-chat` → `config.LLM_MODEL`（单一来源），避免开发/探路脚本照旧口径跑到死地址或下架模型。

### 4. 文档与模板口径修正

- `README` / `HANDOVER`：默认模型改 `deepseek-flash`；桥改口"已挂载进后端，无需单起"；验证命令 `8011/healthz` → `8010/bridge/healthz`
- `.env.example`：桥区段说明 `LLM_BRIDGE_URL` 仅 `ollama`/`openai` 直连用
- 这些修正落在 tag 之后的 `72eb12f` / `b3a0016`（见末尾"发布卫生"）

### 5. v1.4.2 → v1.4.3 期间累积的其他修复

- 「保存为我的辩题」不再丢掉领域（`domain`）
- 写接口错误语义统一走状态码（剩余 5 处 `200 + {"error"}` 收敛）
- 前端检查 `res.ok`，让失败的写入不再显示成功（配套后端错误码）
- 协议桥上游失败不再伪装成"模型答了空"
- 桥的 CSRF 豁免用例不再打真实上游、不再依赖本机是否配了 key
- `bootstrap.sh` 钉住 mavis v1.3.3，别跟着默认分支走
