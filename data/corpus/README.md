# 法源语料目录

把法条全文、判例集、学说摘录放进这个目录，引用核验就会从"模型自称"变成**程序化核对**。

> 本目录（含本 README）**不会**被当成语料加载：以 `README` 开头或以 `_` 开头的文件会被跳过。

---

## 一、结构化法条（能判到「已核验」）

新建 `laws.json`：

```json
{
  "《中华人民共和国著作权法》": {
    "第三条": "本法所称的作品，是指文学、艺术和科学领域内具有独创性并能以一定形式表现的智力成果……",
    "第十一条": "著作权属于作者……如无相反证明，在作品上署名的公民、法人或者其他组织为作者。"
  },
  "《中华人民共和国民法典》": {
    "第五百零九条": "当事人应当按照约定全面履行自己的义务……"
  }
}
```

也接受数组写法：

```json
[
  { "law": "《著作权法》", "article": "第三条", "text": "……", "source_type": "法律" }
]
```

**条款号写法随意**：`第十一条`、`第11条` 都能识别（内部会归一到同一个键）。
法名也容忍差异：`《著作权法》` 与 `《中华人民共和国著作权法》` 视为同一部。

## 二、自由文本（只能判到「存疑」）

`.md` / `.txt` 文件放进本目录即可，用于模糊检索（判例集、学说摘录等）。

**为什么只能判"存疑"**：自由文本无法证明"条款号"与"内容"的对应关系。
系统只有在结构化语料里确实查到该条款时，才会给「已核验」并附上原文为证。

---

## 三、核验状态的含义

| 状态 | 含义 |
|---|---|
| **已核验** | 结构化语料里确实有这一条，附原文为证 |
| **存疑** | 该法存在但语料里没这一条（可能编造，也可能语料不全）；或只在自由文本里出现 |
| **未核验** | 语料里根本没有这部法 |

**判定是保守的**：宁可信其有风险，也不给虚假的"已核验"。
汇报里的 `待核验` 标记与本目录的核验状态是两回事——前者是模型自我声明，后者是程序核对结果。

---

## 四、语料从哪来

- 国家法律法规数据库（flk.npc.gov.cn）可下载法律全文；
- 最高人民法院官网的指导性案例、公报案例；
- 自己整理的判例与学说摘录（放进 `.md`/`.txt` 即可）。

> ⚠️ 请注意：语料缺失不等于引用错误，语料里有也不等于引用恰当。
> 本功能只回答一个问题——**这条引用在所给语料中是否存在**。
