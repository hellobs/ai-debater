**——决定本项目架构走向的三项实验**

| 日期 | 2026-09-29 |

---

## 摘要

本项目**基于 [`mavisframework`](https://github.com/hellobs/mavis) 开发**，因此其可采用范围必须先经检验。
本文记录阶段 0 的三项实验：验证底座联通（A）、检验 `Agent` 能否充当参谋（B）、
验证降级方案（C）。实验在**只读约束**下进行，框架仓库一行未改。

结果为：底座联通**成立**（A）；`Agent` 充当参谋**架构性不成立**（B），其失败过程本身构成证据；
降级方案**成立且延迟达标**（C）。据此，本项目确立架构决策 —— **只采用框架的基础设施半边
（模型接入 / 后续扩展为提示词模板与插件总线），并行编排自建**。

**关键词**：框架评估；只读依赖；协议桥；结构化输出；时间预算；降级方案

---

## 1. 研究问题

ai-debater 需要一个能承担**并发约束、时限预算与失败语义**的底层接入层。候选基座为
mavis v1.3.3。本阶段回答三个问题：

- **Q1**：框架的模型接入通道能否在不改动框架的前提下打通？
- **Q2**：框架的 `Agent` 能否被塑造成"参谋"——即产出建议文本而非行动计划？
- **Q3**：若 Q2 不成立，降级方案能否满足现场延迟目标（< 2s）？

---

## 2. 方法

### 2.1 三项实验

| # | 实验 | 目的 |
|---|---|---|
| A | `create_llm_provider(provider="openai")` 经协议桥直连模型 | 验证"底座联通"是否成立（Q1） |
| B | 构造 `Agent` 并驱动 `think()` 一步 | 验证 `Agent` 能否被塑造成"参谋"（Q2） |
| C | 三路参谋（反驳 / 质询 / 审计）并行 | 验证降级方案的可用性与延迟（Q3） |

### 2.2 只读约束

实验**不采用 fork、monkey patch 或子类覆写**等修改手段。该约束保证结论的**内部效度**：
若允许改动框架，则观测无法区分"框架的能力"与"改动后的能力"。

---

## 3. 结果

### 3.1 实验 A —— 底座联通：**成立**

```
is_available = True
latency      = 0.85s
output       = '法律涵摄是将案件事实置于法律规范构成要件之下，以推导出法律效果。'
```

框架的 `OpenAIProvider` → 协议桥 → Anthropic 协议网关，链路打通，输出为语义正确的中文法律表述。

### 3.2 实验 B —— 以 `Agent` 充当参谋：**不成立（架构性）**

逐步推进的过程本身即为证据：

| 轮次 | 结果 | 耗时 / 调用数 |
|---|---|---|
| 第 1 次 | 崩溃：`'>' not supported between 'str' and 'int'` | **64.93s / 12 次**（10 次重试 + 每次 `sleep 5s`） |
| 修正桥：结构化输出 | 前进至 `schedule_daily` 后崩溃 | 7.47s / 3 次 |
| 修正桥：JSON 形状修复 | 日程装配成功 → 崩溃于 `time_format_cn` | 5.96s / 3 次 |
| 替换为真 `Timer` | 前进至 `poignancy_event` → 崩溃于 `tile.events` | 6.97s / 4 次 |
| 补全 tile 属性 | 前进至 `percept` → `determining action` → 崩溃于空 spatial tree（`IndexError`） | 7.08s / 4 次 |

**每修掉一处缺陷，立即暴露下一个隐式接口依赖。** 这不属于实现瑕疵，而是框架的形态：

1. `Agent.completion()` 只识别框架写死的 `prompt_*` 集合（`wake_up` / `schedule_*` / `determine_*` /
   `describe_*` / `decide_*` / `summarize_*` / `generate_chat` / `reflect_*` / `retrieve_*`），
   **不存在"给出参谋建议"这一类**。
2. `MAVIS_PROMPT_DIR` 只能替换模板**文本**，无法替换方法集合；占位符由 Python 方法决定。
3. `Agent.think()` 是"日程 → 感知 → 定行动 → 移动 → 计划 → 反思"的**生活仿真管线**，
   产物为行动计划与移动路径，而非建议文本。
4. 要使其跑通，必须提供**真实的 `maze` + 完整 `spatial.tree` + 可用日程** ——
   而这些与"现场向使用者给出建议"这一任务形态无关。

### 3.3 实验 C —— 降级方案：**成立**

```
--- 反驳手（1.26s）---
1. 著作权法保护的是"智力成果"而非"人"本身，法人作品即非自然人创作却享有著作权，
   可见主体资格可拟制，AI 同理。
2. 若只问"谁是人"，则 AI 生成内容永远无法保护，但法律应回应现实……

--- 质询手（1.34s）---
1. 法人不是人，为何法人作品能享有著作权？
2. 摄影机自动成像，为何照片仍受著作权保护？
3. 用户对 AI 输出有独创性贡献，为何不能享权？

--- 逻辑审计员（1.05s）---
偷换概念：对方将"著作权主体须为自然人"偷换为"只有自然人直接生成才受保护"……

总墙钟 = 1.34s    最慢一路 = 1.34s    串行估算 = 3.65s    并行收益 = 63% 节省
```

**三路并行，总耗时等于最慢的一路** —— 这正是现场模式所需的形状，输出质量可直接使用。

---

## 4. 讨论：桥必须承担的两项框架未做之事

两项问题均出在桥内，与框架本身无关：

1. **框架不检查 HTTP 状态码**：它只读 `choices[0].message.content`。桥在出错时若返回非 JSON，
   将触发 10 次重试 × `sleep(5)` = **50 秒静默失败**。⇒ 桥必须始终返回合法 JSON 体。
2. **结构化输出须在桥内兜底**：框架依赖 `response_format`（json_schema）取得结构化结果，
   而 Anthropic 协议无此字段。若直接丢弃，模型将回自然语言 → 框架解析退化为字符串 →
   `schedule.update(<字符串>)` 直接崩溃。⇒ 桥须做两件事：将 schema 写入系统提示，
   **并对返回结果做 JSON 形状修复**（补 `res` 外壳）。
   修正后：**64.93s → 5.6s，12 次调用 → 3 次，零失败**。

## 5. 结论与架构影响

| 问题 | 结论 |
|---|---|
| 框架的 LLM 通道能否使用？ | **能** —— `create_llm_provider` + 协议桥，零改框架 |
| 框架的 `Agent` 能否充当参谋？ | **不能**（架构性不成立），依据见 §3.2 |
| 框架在本项目中的定位 | **基础设施层**（模型接入，后续扩展至提示词模板与插件总线），非 Agent 运行时 |
| 并行参谋如何实现 | 自建：共享单例 provider + `ThreadPoolExecutor` |
| 现场延迟是否达标？ | 达标。三路并行 1.34s，目标 < 2s |

**关键设计决定：`mavis_bridge.py` 为唯一接触面。** 全部辩论业务逻辑位于框架之外 ——
这既符合框架自身的契约红线（框架源码禁止出现业务词汇），也避免被其空间 / 日程模型约束。

---

## 6. 局限

1. **单案例观测**。本阶段仅覆盖一种任务形态（并行参谋），结论不构成对框架全部能力面的评价；
   后续阶段据此扩大了承载范围，结果见 [`mavis-gap-report.md`](mavis-gap-report.md)。
2. **实验 B 的失败记录依赖当时的修复次序**。表中轮次反映的是"修正一处即前进一格"的观测序列，
   并非独立的重复实验。
3. **网络与账户条件未做变量控制**。延迟数据在当时的网关条件下测得。
