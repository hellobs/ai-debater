## 1. 产品定义的沿革

### 1.1 第一次修正：从「AI 互搏」到「并行参谋团」

**背景**　用户提供的初始交接文档所描述的产品形态为「正反方 AI 自动互搏 + 裁判打分」。

**依据**　开发中途用户作出关键澄清：

> **「我这个多 Agent 是同时为我出主意的」**

**决策**　产品**整体重新定义**（PLAN v1.0 → v2.0；v1.0 全文保留于提交 `871b0a5`）：

- 不是 AI 打 AI，而是**一支并行参谋团，全部与使用者同阵营**；
- AI 仅产出建议，**采纳与否由使用者决定**；
- 主场景为**现场辅助**（使用者处于台上，对方陈述结束后系统给出建议）。

**理由**　该转向同时降低了架构复杂度：**既无回合交战，便不存在"谁该发言""谁获胜"的问题**，
原方案中的**赛制状态机、发言权交替、胜负判定与 Elo 评级全部被移除**。

**后果**　**接手者须注意**：若未读到本节，容易"出于善意"将互搏、裁判与赛制重新引入 ——
那将推翻整个设计。

### 1.2 第二次修正：从「法学辩论台」放宽为「通用辩手台」

**背景**　用户进一步澄清：

> **「我还是希望这个平台是个通用的辩手平台，只不过最终落地是 AI + 法学的」**

起因是使用者发现**界面上仅有一个写死的样例辩题**（`App.tsx` 中的 `SAMPLE_TOPIC` 常量）。
顺此排查，"法学"被固化于**四处**：品牌文案、参谋名册、立场预设、样例辩题。

**决策**　法学是**落地场景**，不是平台的定义。处置如下：

| 层面 | 处置 |
|---|---|
| 品牌 | 统一为「辩手参谋台」，收进 `config.BRAND_NAME`（前端与 FastAPI title 同源） |
| 辩题 | 由硬编码常量 → `configs/topics.yaml`（入仓预设）+ `data/topics.json`（本机自建） |
| 立场 | 由写死的四选项 → **由辩题带出**（`side_a` / `side_b` 属辩题的一部分） |
| 名册 | 由三份副本（类属性 / 无人读取的 YAML label / 前端 `COLUMNS`）→ **一份** `advisors.yaml`，前端读 `/api/health` |
| 场景标注 | 辩题与参谋均带 `domain`，界面按场景分组与打标（`通用` / `AI + 法学`） |

**判据**　核心原则是**单一事实来源**：辩题、名册、品牌各只允许定义一次。
判据具体化为 —— **同一事实在仓库中出现两次以上，即为缺陷的温床**（本轮修正的正是这一项）。

**遗留**　⚠️ 尚有一层未解耦：参谋的**角色指令**仍为法学措辞。之所以不连带修正：
修改提示词即修改模型行为，**必须真跑一轮（5 次上游调用）方可判断优劣**，
依 §5 成本红线不得自行决断。已列为待办，见 `HANDOVER.md` §13 第 3 条。

## 3. mavis 相关结论（有证据链，勿推翻重来）

阶段 0 完成了源码级验证，完整报告见 [`spike-0-report.md`](spike-0-report.md)。

### 3.1 结论：框架仅可作为基础设施层，不可作为 Agent 运行时

**判据**　框架的 `Agent` 无法在不修改源码的前提下被塑造成"参谋"：

1. `Agent.completion()` 只识别框架写死的 `prompt_*` 集合
   （`wake_up` / `schedule_*` / `determine_*` / `generate_chat` / `reflect_*` / `retrieve_*`），
   **不存在"给出参谋建议"这一类**；
2. `MAVIS_PROMPT_DIR` 只能替换模板**文本**，无法替换**方法集合** —— 占位符由 Python 方法决定；
3. `Agent.think()` 是"日程 → 感知 → 定行动 → 移动 → 计划 → 反思"的**生活仿真管线**，
   产物为行动计划与移动路径，而非建议文本；
4. 使其跑通还须提供真实 `maze` + 完整 `spatial.tree` —— 与"现场给出建议"无关。

**证据**　逐轮推进过程本身即为证据：每修掉一处缺陷即暴露下一个隐式接口依赖
（替身计时器缺 `time_format_cn` → `tile.events` → 空 spatial tree 报 `IndexError`）。

### 3.2 采用的方案：仅取基础设施半边，编排自建

最初仅取 `create_llm_provider` 一个工厂做模型接入。**2026-09-30 扩展至三面**
（模型接入 + 提示词模板 + 插件总线），完整清单与证据见 [`mavis-gap-report.md`](mavis-gap-report.md)：

| 能力面 | 接口 | 落点 |
|---|---|---|
| 模型接入 | `mavisframework.create_llm_provider`（顶层 `__all__`） | `backend/app/mavis_bridge.py` |
| 提示词模板 | `mavisframework.prompt.Scratch` | `prompts/*.txt` + `advisors/base.py` |
| 插件总线 | `mavisframework.plugin.PluginManager` | `backend/app/observers.py` |

**并行编排仍为自建**（共享单例 provider + `ThreadPoolExecutor`）。
框架一行未改，且 `backend/app/` 下仅 `mavis_bridge.py` 允许 `import mavisframework`
（`tests/test_mavis_usage.py` 以 AST 扫描守护此约束）。

### 3.3 并行编排实测

三路并行总墙钟 **1.34s**（等于最慢一路），串行估算 3.65s，**节省 63%**。

### 3.4 网关仅支持 Anthropic 协议 ⇒ 协议桥为必需

实测 `ANTHROPIC_BASE_URL` = `https://api.deepseek.com`：
`POST /v1/messages` → **200**；`POST /chat/completions` 与 `/v1/chat/completions` → **404**。

而框架的 `OpenAIProvider` 仅支持 OpenAI 协议 ⇒ 必然无法直连。
**⇒ 自建 `backend/app/llm_bridge.py` 承担协议翻译。**

### 3.5 桥必须兜住的两项（缺失即导致故障）

1. **始终返回合法 OpenAI 响应体**：框架**不检查 HTTP 状态码**，只读
   `choices[0].message.content`。桥在出错时若返回非 JSON，框架将走 10 次重试 × `sleep(5)`
   = **50 秒静默失败**（实测最严重一次 64.9 秒 / 12 次调用）。
2. **`response_format` 须翻译为系统提示并对返回做 JSON 形状修复**：
   框架的 pydantic 模型统一形如 `{"res": ...}`，但模型常将内层对象直接作为顶层输出，
   pydantic 校验失败后框架退化为字符串，随即 `schedule.update(<字符串>)` 崩溃。
   修正后：**64.93s → 5.6s，12 次调用 → 3 次，零失败**。

### 3.6 框架的契约红线

- `tests/test_extension_surface.py` 冻结了 `Game` / `Simulator` / `load_config` 的签名与默认值；
- 框架源码**禁止出现业务词汇**；
- ⇒ **全部辩论业务逻辑必须位于本仓库**。

### 3.7 基础设施半边用满（2026-09-30）

**触发**　用户要求提高框架使用深度，并拍板两项：① 接入深度取"provider 用满 + 插件总线"；
② **只出报告，不修改框架仓库**。

**做法**

1. **`LLMProvider` 由 3 个参数扩展至 6 个**。新增 `caller=`（逐参谋计数）、
   `failsafe=`（失败哨兵）、`callback=`（结果规整）；并将 `is_available()` /
   `get_summary()` / `cache_stats()` 接入 `/api/health`。
2. **提示词迁入框架的模板层**。`prompts/layout.txt` + `roles/*.txt` + `tasks/*.txt`，
   提示词由 Python 长字符串转为可 diff、可版本化、可逐参谋覆盖的数据。
   **迁移经过逐字节核对**：与 git HEAD 中旧 f-string 拼接的输出完全一致
   （由 `test_built_prompt_follows_the_layout_contract` 锁定）。
3. **三个观察者改挂 `PluginManager`**。落库 / 推流 / 指标由内联回调链改为插件，
   从而获得逐插件错误隔离 —— 指标插件抛异常不再连带落库与推流一起失败。

**关键判断**　**`failsafe` 是区分"上游不可达"与"模型返回空"的唯一开关。**
框架的 `completion()` 吞掉全部异常（`llm_providers.py:81-95`）；默认 `failsafe=None` 时两类失败
落进同一分支（返回值仅 `None` 与 `''` 之别，属实现副产品，见 §3.8 ② 与 N1）。
传入私有哨兵后拆为 `error` / `empty` 两个状态 —— 现场不再将其误判为"模型不太会说话"。

**由此暴露的框架缺口**（只报告，不修改）：G1 结果缓存白名单写死调用名（接入方无法登记）；
G2 全局并发闸按 `size` 重建（两个 `concurrency` 不同的 provider 会互相顶掉闸门）；
G3 退避 `sleep(5)` 硬编码；G4 `prompt` / `plugin` 未进入顶层 `__all__`；
G5 `validate_message` 与 `emit` 契约不一致；G6 `Scratch` 借用成本偏高；
G7 **`get_summary()` 的 `R` 并非重试次数**（仅在成功取得响应时递增，抛异常的尝试不计入，
重试 3 次全失败时 `R` 为 0）—— 前端仪表原先将该列标为"重试"，会直接读错，已改为"请求"。
清单、证据与建议改法见 [`mavis-gap-report.md`](mavis-gap-report.md)，复现入口
`backend/spikes/mavis_bounds.py`。

**未做的部分**：C 层（SSE 协议对齐 + snapshot 事件）、D 层（`DecisionEvent` 导出）。
`DecisionEvent` 的 17 个字段仅能填上一部分 —— 如实定性为"部分映射"，不为使用而使用。
仿真半边（`Agent` / `Simulator` / 记忆 / 日程）仍然排除，理由见 §3.1。

### 3.8 将基座事实从文档移入代码（2026-09-30）

**触发**　用户要求 README 更突出框架（"ai-debater 有点像 mavis 的 field test"），并继续推进项目。

**决策**

**① 「用了框架什么」写入代码，不再仅存于文档。**
`mavis_bridge.SURFACES` 为唯一事实来源，`runtime_info()` 将真实状态拼入
（`mavisframework.__version__` 的真实版本号、只读标记、唯一接触面、`prompts/` 的真实清单），
`/api/health` 的 `mavis` 块、导出报告页脚、前端「现场仪表」均读取它。

判据来自本项目已经历的两次失误：README 写"6 条缺口"而报告实为 7 条；
仪表将 `R` 标为"重试"（上游全挂时显示"重试 0 次"，恰好掩盖故障）。
**同一事实在仓库出现两次以上即为缺陷温床**，故本轮令其只剩一份，
并新增测试核对每一面的 `used_in` 指向真实函数。

**② 引用核验增补第二个维度：内容一致性，但只披露、不自动降级。**
条款号真实存在，不代表模型为其配置的条文内容正确 —— 实测中模型曾写出真实条款号 + 编造内容，
旧版仍判「已核验」。现在抽取引用之后紧随的"声称内容"，与语料原文比对
**最长公共子串重合度**，并并排展示。

**刻意不改变 `status`**：存在性（有无该条）与一致性（内容是否正确）是正交的；
低重合可能源于编造，也可能源于合理意译，**裁定权在人**（与产品定位一致：AI 仅出主意）。
自动降级会把"意译概括"批量标为"幻觉"，劣于不标 —— 若要降级，须先有真实语料下的误杀率数据。
抽不出内容（或归一化后不足 6 字）即不比对：宁可不结论，也不给噪声值。

**③ 归属关系单一句式化。**
`mavis_bridge.BASED_ON` 记基座发行包名，`declaration()` 给出唯一句式——
「本项目基于 `mavisframework` vX 开发（只读依赖，一行未改）」。
调用方只可替换**框架名的呈现形式**（Markdown 链接 / HTML 粗体 / 纯文本），不可改句式；
README、导出报告与界面脚注由此同源。

**④ README 章节顺序按叙事权重排列。**
「框架实地检验」置于第 2 章（紧跟摘要与范围界定之后），框架徽章置于徽章行首位，
架构图中 `mavis_bridge` 加紫色描边并在图注中点名。

### 3.9 让缺口报告的结论可机器复核（2026-09-30）

**背景**　`docs/mavis-gap-report.md` 是对**某个具体版本**的评估，不是永真命题。
框架一旦修掉某处，报告即由"结论"退化为"过期说法"，而文档不会自己报错。
同时，报告写了 N1–N4 四条接线注意，探针却只覆盖 N2 / N3 —— **证据有缺口**。

**决策**

1. **探针的人读输出与机器断言共用同一份证据。** `backend/spikes/mavis_bounds.py`
   改造为：每个探针先算出 `evidence` 字符串列表与 `reproduced` 结论字段，
   `main()` 只负责渲染成人读格式或 `--json`。
   "打印一套、断言另一套"正是本项目明确要避免的双份事实。
2. **新增 `--json` 模式。** 机器读模式下关闭 mavis 的 logger ——
   实测其日志默认写 **stdout**（不是 stderr），不关会把 JSON 弄脏。
3. **补上 N1 / N4 探针。** 至此 G1–G7 与 N1–N4 **条条可复现**。
4. **`tests/test_mavis_gap_report.py` 守住结论。** 在**子进程**里跑探针
   （探针会动 mavis 的进程级并发闸 `_GLOBAL_SEM`，隔离最干净），断言：
   7 处缺口 + 4 条注意仍能复现；报告里的编号集合 == 探针的编号集合；
   报告汇总表的严重度与探针一致。
5. **顺带修正一处措辞过强的表述**：N1 原先写作"两类失败同形"。实测为
   `failsafe=None` 时上游重试耗尽返回 `None`、模型返回空内容返回 `''` ——
   **并非完全同形**，但该差别属实现副产品，任何按空值归并的调用方
   （本案例的 `out is None or len(out) == 0`）都会把二者收进同一分支。
   已按实测改写 README / HANDOVER / 本文件 / `mavis_bridge._Failsafe` 文档串共 7 处。
   —— 结论没变，但"同形"这个词把机制说错了，而检验报告里不该有说不准的机制。

### 3.10 领域措辞关进提示词包（2026-09-30）

**背景**　平台定位是「通用辩手参谋台」（决策 13），品牌、配置、辩题库、名册都已中立，
但**参谋的措辞仍按法学写**：反驳手被要求"大前提 = 法律规范"、风险提示员要找"法源不稳"、
论证策略师整路就是法律解释方法。通用辩题走同一条路，于是模型也拿法律框架推理。
**它不报错** —— 只是让输出悄悄换了个学科视角，这正是最难发现的一类缺陷。

**两条备选路线**

| 路线 | 做法 | 判断 |
|---|---|---|
| 低成本 | 把法学词全局换成中立词（"法律涵摄" → "三段论涵摄"、"法源不稳" → "依据不稳"） | ❌ 未采纳 |
| 结构化 | 领域提示词包，按辩题 `domain` 选包 | ✅ 采用 |

未采纳低成本路线的原因：**它会改变法学场景的输出风格**，而法学正是本项目的落地场景。
"两边都照顾到"的写法会把措辞稀释成谁都不精确的中间态；包让两套措辞各留在自己包里，
法学场景一个字都不动。

**决策**

1. **`prompts/packs/<包>/{roles,tasks}/`，`layout.txt` 留在顶层共享。**
   领域差异只在角色指令与任务说明里；总装骨架换领域不该换（"换一个领域只换措辞"是解耦的定义）。
2. **`legal` 包逐字节等于解耦前的 `prompts/{roles,tasks}/`。** 迁移用 `git mv`，
   提交显示为纯 rename（0 行增删）。**法学辩题零回归**不是自评，是可核对的 diff。
3. **精确匹配 + 默认包，绝不猜。** `configs/prompt-packs.yaml` 的 `domains` 列表逐字匹配；
   未认领的领域与自由输入（无 `domain`）落默认包并写一条 debug 日志。
   猜错时提示词会安静地换成另一套框架 —— 宁可落默认包。映射写在配置里，改包名不动代码。
4. **包必须自包含，`preload()` 遍历所有包做启动自检。**
   两个包里 `auditor` / `questioner` 逐字节相同，这不是重复：一个包能被单独替换的前提
   就是它自带完整的 5×2 份模板。只查默认包是不够的 —— 选包发生在请求里，
   等发现 legal 缺一份模板时只能 500 或静默降级，两者都比"起不来"更糟。
5. **顺带找出另外两条泄漏路径**（只改提示词是不够的，这是本轮最重要的发现）：
   - `schemas.py` 的字段描述会被 mavis 塞进 `response_format.json_schema`
     **一起发给模型**（`mavisframework/runtime/llm_providers.py`）。
     "大前提：所依据的法律规范（法条名称+条款号）"不是注释，是提示词。
     现已改为只写跨领域成立的话；**取值枚举交给包**（"取值见任务说明"）——
     枚举写在这里等于让它压过任务说明，还会和包里打架（法律包写「法源不稳」、通用包写「依据不稳」）。
   - `advisors.yaml` 与参谋类里的**显示名**。`解释方法策略师` → 领域中立的 `论证策略师`；
     名册里的 `domain: 法学` 标记解除（它表达的是"这一路只懂法律解释方法"，
     包机制之后这个前提不成立了）。界面显示名只有一份，不能在两个包里各写一个 ——
     前端列头读的是 `/api/health` 的名字册，它不知道本轮选了哪个包。
6. **`domain` 由前端搬运，后端不按标题反查辩题库。**
   反查看着更省事，但标题随时可改，反查会静默选错包。代价是第三方直接调 API 时必须自带 `domain`。
7. **本轮不落库所用包。** `sessions` 表加列要一次 `ALTER TABLE` 迁移，属于另一件事；
   `_prepare()` 的 docstring 与 HANDOVER 待办里如实记下（复盘报告暂时无法回溯当轮措辞）。
8. **验收分两层：结构与措辞（0 消耗，已证明）+ 质量（一轮实测，见下）。**
   已证明：选包正确、通用包里无法学措辞、json_schema 里无法学措辞、法学包逐字节零回归。
   而"通用包产出更好"**不是**一轮实测能回答的问题（n=1、无盲评），实测只回答
   "换包是否真的改变了产出"。

**实测（2026-09-30，6 次上游调用）**

复现入口：`backend/spikes/pack_quality.py`（带 `--dry-run`，只看两包提示词、0 消耗）。
做法：同一道通用辩题「大学应当把人工智能设为必修课」，**只换 `domain`**（⇒ 只换包），
其余输入完全相同；跑两包内真正有差异的三路 —— `rebutter` / `strategist` / `risk`
（`auditor` / `questioner` 两包内逐字节相同，跑它们只是白花钱）。6 次调用全部 `status=ok`。

| 路 | general 包 | legal 包 |
|---|---|---|
| 反驳手 | 大前提落在**教育学**：「大学教育目标具有多元性，通识与专业能力可同时培养」 | 大前提被拽向**法条**：「（待核验：高等教育法关于本科教育应使学生掌握现代科技文化知识…的规定）」 |
| 策略师 | 尺度：价值排序 / 后果权衡 / 概念界定 | 方法：目的解释 / 体系解释 / 文义解释 |
| 风险提示员 | 风险类型：对方陷阱 / 我方薄弱 / 依据不稳 | 对方陷阱 / 我方薄弱 / 事实不清 |

两点观察（**n=1 题 × 1 次/格，是"看到了什么"，不是"证明了什么"**）：

- **解耦确实生效，且错配的代价是可见的。** 同一道非法律题在 legal 包下会被主动拽去**找法条**，
  而那些条款与本辩题无关（模型自己也只能标「待核验」）。这从反面印证了决策 3
  「精确匹配、绝不猜」的必要性 —— 选错包不报错，只会让依据悄悄换成另一套学科框架。
- **两包都在标「待核验」，这不是 legal 包独有的缺陷。** `data/corpus/` 为空，
  两包都给不出可核验出处，标「待核验」正是第 2 条纪律要求的行为。

⚠️ **本轮没有、也不能证明"通用包产出更好"。** 没有盲评、没有评分标准、n=1。
"更好"要的是人读了以后的主观判断，不是 6 次调用能给的。

**代价与已知局限**

- `retrieval/`（法源检索与引用核验）**按设计就是法学专用**的，没有被也不该被包机制覆盖。
  通用辩题下这一面板不适用，但它只核验引用、不参与生成，所以不会误导。
- 每加一个新参谋，要在**每一个包**里各补一份 `roles` / `tasks`。这是自包含的代价，
  漏了会在 `load_roster()` 当场报错，不会静默降级。

## 4. 架构层面的关键取舍

### 4.1 台账为何必须外置

框架的记忆是**非结构化情景记忆**（三因子检索：近因 / 重要性 / 相关性），
metadata 为固定 schema，**写入额外字段会直接 `TypeError`** —— 结构化论点卡片无法容纳。
⇒ 台账置于本项目自有的 SQLite（`backend/app/ledger/store.py`）。

### 4.2 防立场漂移设置两道闸

1. **预防**：每次分析将台账中仍成立（`standing`）的主张**注入参谋提示词**；
2. **检测**：`check-consistency` 端点将新建议与台账比对，找出**不能同时为真**的冲突，前端标红。

**检测刻意不置于 `/api/analyze` 热路径** —— 现场延迟敏感，由前端在建议返回后再调用一次。

**实测**：故意喂入一条与台账相反的主张 → 准确命中；同时**正确放过无关主张**（无误报）。
"宁可漏报，不可误报"是刻意的：一个乱报冲突的检测器等价于不存在。

### 4.3 时间预算的正确语义

现场的关键不是"全部返回"，而是**到点交付已就绪的部分**。

- 超预算的参谋标记 `timeout` 并立即推送，**不阻塞**其余几路；
- **实现要点**：`concurrent.futures.wait(timeout=)` 循环 + **`pool.shutdown(wait=False)`**
  —— 不可等待线程收尾，否则"按时交付"失去意义；
- **实测**（预算 1.6s）：质询手 1.05s ✓ / 审计员 1.22s ✓ / 反驳手 timeout，**总耗时 1.62s 返回**。

### 4.4 引用核验为何采用保守判定

三级状态**必须保守**：

| 状态 | 含义 |
|---|---|
| **已核验** | **结构化语料**中确有该条，附原文为证 |
| **存疑** | 该法存在但语料中无该条；或仅命中自由文本 |
| **未核验** | 语料中不存在该法 |

**已修正的两处缺陷（均由测试发现）**：

1. 仅引法名而不给条款号时，`lookup(law, "")` 会返回该法**首条** → 被误判为「已核验」。
   修正：无条款号一律判「存疑」，**不得以首条兜底**（那属假阳性）。
2. 条款缺失时将"该法首条"作为 `evidence` 显示 → 形似在为该条提供佐证。
   修正：不显示证据。

**增补的第二个维度（2026-09-30，见 §3.8）**：上述三条仅回答**存在性**。
条款号真实存在而内容为编造，是完全可能的 —— 旧版在此情形下仍判「已核验」。
现另有一组**内容一致性**字段（`claimed` / `match` / `content_ok` / `match_low` /
`content_suspect`），只披露不自动降级，理由见 §3.8 ②。

### 4.5 PDF 为何不直接生成

中文 PDF 需内嵌 CJK 字体（fpdf2 / reportlab 均须挂载 TTF），**缺字体会渲染为方块**。
⇒ 后端产出**打印优化页面**，由前端唤起打印对话框，使用者选择"存储为 PDF"。
浏览器打印使用系统字体，零依赖且排版最优。理由已写入代码注释与 README。

### 4.6 Word 导出的中文字体陷阱

python-docx 仅设置 `style.font.name` **不足够**，必须显式设置 `rPr/rFonts` 的 **eastAsia**
属性，否则 Word 打开后中文观感会回退。

### 5.1 事实

| 事实 | 说明 |
|---|---|
| **点击一次分析 = 5 次上游调用** | 5 路各 1 次 |

### 5.2 开发方已犯的错误（引以为戒）

**未先询问即执行真实压测**，且阶段 0 那一轮 JSON 未修正的失败单次消耗 12 次调用。

### 5.3 正确的节约方式

1. **能在本地计算即在本地计算**：150 项单测、`python -m benchmarks check/eval` 均为 0 消耗；
2. **以临时名册仅启用需验证的路**：

4. `benchmarks run` **不带 `--live` 时仅报告预计调用量后退出**，防止误触；

6. 彻底杜绝误触：`pkill -f app.main; pkill -f app.llm_bridge`。

## 6. 环境与工具陷阱（本机特有，换机可能不同）

1. **npm 创建 `node_modules/.bin` 被策略拒绝**（`CODEBUDDY_BROKER_DENY`）→ reify 整体中断、

3. **`nohup … &` 启动的进程随 shell 退出被回收** → 表现为"刚检查仍健康，下一步即 404"。
   须使用受管的后台任务方式启动。
4. **沙箱内默认无网络**（HTTPS 经代理 502）→ git 推拉 / 安装依赖 / 联网检索均须显式放行。
5. **`app.config` 在导入时读取环境变量** → 测试必须**先设 env 再 import**。

6. `dangerouslyDisableSandbox` + 引号嵌套复杂的 curl/python 组合命令会报
   `sandbox-center cmd decisionRecord missing actual resource subject`；
   改为"先 curl 落文件、再单独解析"即可绕过。

## 9. 上游可运行时配置 ⇒ 协议桥并入后端进程（2026-09-30）

**起因**：换模型/换网关原本只能改 `.env` 再重启两个进程，界面上做不出一个下拉框。
而"用哪个模型"恰恰是最该由使用者当场决定的事（本机 8B 免费、云端快但计费）。

**决定**：
- 新增 `app/upstream.py`：当前上游（kind=ollama/openai/anthropic、base_url、
  key、model）是**进程内存里的一个配置对象**，`POST /api/upstream` 运行时改，
  改完 `mavis_bridge.reset_provider()` 重建 mavis provider（构造时定死地址，改不了）。
- `llm_bridge.py` 的凭据从模块级常量改为 `CFG` 对象：既能独立跑
  （`python -m app.llm_bridge`，8011，行为不变），也被后端 `app.mount("/bridge", ...)`
  —— anthropic 形态下 mavis 自调用 `http://127.0.0.1:<端口>/bridge/v1`，
  **云端模式从此只需两个进程**（后端 + 前端），不再强求先起桥。
- 模型清单靠探测：Ollama `/api/tags`、OpenAI `/v1/models`、Anthropic `/v1/models`；
  探测不到（部分网关不实现）就**如实报错退回手填**，不拿写死的清单冒充。
- 凭据**只驻留内存**：不落盘、不回显、对外只有 `key_set: bool`；
  `api_key` 走 POST body，不从 URL 传（明文密钥不该进查询串/日志/浏览器历史）；
  `api_key=None` 语义是"不动"，与"清空"分开 —— 否则只换一次模型就得重填一次密钥。

**内层刀对齐**：切上游不影响预算语义 —— 单次调用上限仍是
`max(预算, LLM_TIMEOUT_S)`（见本次更早的提交）。

**界面**：设置面板新增「模型与上游」（形态/地址/密钥/模型探测 + 手填）；
延迟仪表（P50/P95 面板）**从界面移除**（后端 `/api/metrics` 保留，导出与测试仍在用）。

## 10. 上游配置可保存到本机浏览器（2026-09-30）

**起因**：上游只在后端进程内存里（§9），重启后端就要重填地址和密钥 ——
对开发干净，对配了云端 API 的使用者是每次重填。

**决定**：
- 新增 `frontend/src/upstreamStore.ts`：**多份命名配置**存浏览器 `localStorage`
  （本机 Ollama 一份、云端 DeepSeek 一份，下拉切换，选完即载入并应用）。
- 页面加载时自动把**上次那份**回灌给后端（后端内存重启即空，需这一步补上）；
  失败静默跳过 —— 自动恢复是便利，不该变成开机弹错。
- 后端**仍然一行不落盘**：持久化只发生在前端，且明文（不做 base64 之类
  "看起来安全"的混淆）。分工理由：仓库与 `.env` 会被提交/分享，浏览器 profile
  不会；清除只需一键。这件事在界面上写明了，不遮掩。
- 密钥**永不回显**到界面：载入已保存配置时输入框留空，只提示"已保存一把，
  留空即沿用"；「应用」时未重填就沿用那份已存的 —— 否则改个模型就把密钥洗掉。

**代价（如实记录）**：localStorage 明文存 API key，本机其他程序/脚本可读。
本项目定位是本机工具，接受这个代价；若要更强保证，应走系统密钥链，
那是另一件事，别在这里假装加密。

## 11. 语音输入（ASR）选型：本地 SenseVoice + 手动分闸（2026-09-30）

**背景**　阶段 7（语音实时转写）自立项起被「方案三选一待拍板」阻塞（HANDOVER §12.2）：
浏览器 Web Speech / 本地 Whisper / 云 ASR。用户在评审中确认两件事：**手动分闸**
（对方开口点开始收音、说完点结束）是正确的说话人区分方案；**走本地推理路线**。

**决策**　
- 引擎选 **sherpa-onnx + SenseVoice-small（int8）**，不是三选一表里的任何一个 Whisper 变体。
  依据（2026-09-30 实测）：SenseVoice 在中文上准确率优于同尺寸 Whisper 且 CPU 快一个量级
  （本机实测 9.45s 音频 1.4s 转写，RTF≈0.15，且自带标点与数字规整）；sherpa-onnx 是
  自包含 wheel（无 torch），Python 3.13 / Windows 轮子实测可用。
- Web Speech 只能当备选：Chrome 的 SpeechRecognition 是服务端识别、音频发 Google 服务器，
  **国内直连不可用**（MDN 证实）；Edge 走 Azure 可用，但绑浏览器、绑网络，不能当现场主力。
- 云 ASR 撞**成本红线**（§成本红线），且现场网络是已知风险，除非本地准确率实测不达标。
- 交互取**手动分闸**，不做说话人分离（diarization）：现场只有两三个人说话，人手一按
  就能区分，不值得引入一套说话人日志。
- 转写结果**只填可编辑输入框，绝不自动触发分析**：识别错字由人核对后再提交——
  「以什么文本去问参谋」是决策，决策权归使用者（与 §1.1 的产品定义同源）。

**后果**　
- 依赖新增 `sherpa-onnx`（requirements.txt）；**模型不入仓**（约 228MB，gitignore），
  由 `scripts/fetch_asr_model.sh` 从 hf-mirror 一次性下载——刻意只拉 int8 权重 +
  tokens 两个文件，**不下 GitHub release 整包**（1.1GB，内含用不到的 fp32 权重）。
- 引擎不可用（未下模型 / `ASR_ENGINE=none`）时 `/api/health` 如实报
  `asr.available=false` 与原因，界面收音按钮禁用并说明——不做静默降级。
- 一期为**批式**（整段收音、结束后转写）。流式（边说边出字）留二期：
  sherpa-onnx 有现成流式 Zipformer 模型，届时加 WebSocket 分片上传即可，
  `Transcriber` 抽象与前端采集格式都为它留了口子。
- 实测留档：模型对全零静音段可能输出「嗯。」之类的填充词——静音不是错误，
  零碎内容由人在输入框里删，测试断言只要求「正常响应」而非「空文本」。

## 12. 现场工作台改版：Menu 分区 / 状态持久化 / 语料界面导入（2026-09-30，随 1.2.0）

**背景**　实际使用暴露三个摩擦：左栏六个分区竖排把现场高频输入顶出首屏；
刷新 / 误关标签页会清空现场攒出来的输入（对方发言不会再说第二遍）；
引用核验的语料只有命令行导入一条路，队友在现场不会开终端。

**决策**　
- **左栏 Menu 三分区**：「现场输入」（①–④ + 生成按钮，默认）/「模型与上游」/「服务状态」。
  只动展示层，表单状态全在组件顶层，切换不丢内容；后端未连通时状态分区亮红点提示。
- **现场状态持久化**（`frontend/src/liveStateStore.ts`）：辩题 / 立场 / 对方发言 / 预算 /
  sessionId 存 localStorage（键 `debater.liveState.v1`），挂载时恢复并接回台账。
  **恢复优先于"默认选第一条辩题"的引导**（恢复过就置 bootstrapped 标志）。
  信任模型与 upstreamStore 相同：明文本机存储、不上传、不假装加密。
  参谋结果**不**恢复——那是上一轮的输出，恢复它反而让人误以为是本轮。
- **语料界面导入**（`POST /api/corpus/import` + 引用核验面板控件）：与 CLI 共用
  `statute_text` 解析，逻辑只写一遍；同名法整体替换；导入即热重载，不必重启。
- **顺带的解析器修复**：`guess_law_name` 剥书名号——界面引导写《XX法》，
  guess 却只认裸名，导入直接报「无法识别法名」。实测咬到后修在解析器
  （官方全文也常带书名号），不是绕过。

**后果**　
- 用户导入的真实法条语料（8 部全国性法律，官方公开文本）**随仓库分发**：
  克隆即得「已核验」能力，呼应"新人拉下来能跑通"的验收线。不想分发删掉
  laws.json 即可，导入界面随时能补回。
- 后端不新增任何持久化：现场状态在前端，会话仍只在后端 SQLite——两侧
  各管各的，重启谁都不丢该留的东西。

## 13. 第二轮体检：分析端点改 POST / 持久化空快照缺陷 / mock 上游工具（2026-09-30）

**背景**　第一轮体检（同日）报出 P2-1：分析走 GET-SSE，对方发言在 query 里——实测
uvicorn 请求行 ~32KB 通过、64KB 拒绝（约 3500 中文字撞墙），且发言全文进访问日志。
语音转写（一期）会产出长文本，问题从理论变成现实。

- **`POST /api/analyze/stream`**（输入 JSON body）成为前端在用形态；GET 保留给
  脚本与旧客户端，两者事件序列完全一致（共用 `_analyze_stream_response`）。
- 前端弃用 EventSource，改 **fetch 流式读取 + 自行解析 SSE 块**（AbortController 取消）。
  事件语义与旧版逐一对齐——尤其保留「出错不自动重跑」：重连会再花一次 token。
- **修复持久化空快照缺陷**（第二轮实测咬到）：保存过空辩题的状态会在下次加载时
  抑制「默认选第一条辩题」的引导，辩题框卡死为空、提交永远禁用。现在只有
  恢复到**非空辩题**才抑制引导。
- **新增 `scripts/mock_upstream.py`**：按 response_format 的 schema 名返回合规假
  数据的本地 mock 上游（OpenAI 协议）。用它切上游即可**零成本跑通整条热路径**
  （POST-SSE → 五路并行 → 落库 → 渲染 → 一致性检测）。

**实测留档**　mock 全链路：5 路 0.14s 全 ok、17 个可编辑字段渲染正确、一致性检测通过。
长音频 ASR：80.7s 音频 2.75s 转写（RTF=0.03），跨窗文本连贯。检索核验真实语料
（8 部 / 2366 条）0.6ms、引用全「已核验」。SQLite integrity_check ok。

## 14. UX 第二批：核验自动化 / 语音流式二期 / 法学辩题扩充 / CI（2026-10-01）

**背景**　用户体检清单（HANDOVER「用户体检待办清单」）中四项被点名：
UX-2（核验自动化）、UX-3（流式 ASR）、UX-7（用户拍板方向为「多补 AI+法学题」，
而非原方案的"补非法律题"）、上 CI。

  批式管质量**是实测结论（流式 small+greedy 有结巴式重复），二者并存不互替。

## 16. 反馈闭环与通用知识库 / 3+2 布局改版 / v1.4.0 体检（2026-10-04）

**背景**　项目已从 v1.2.1 长到 v1.4.0（反馈闭环 + 证据落库 + 通用知识库 + 3+2 布局 + 界面减字）。
本轮对 v1.4.0 做一整轮体检（测试 / 构建 / 新增模块合规与安全 / CSRF / 端到端零消耗 / 窄屏几何走查），
顺带把两个新模块的取舍落进记录。

**决策**
- **知识库不做索引持久化**：`app/knowledge.py` 每次 `rebuild()` 全量重建 char-bigram TF-IDF。
  换来的是"上传即生效、永远没有索引损坏/过期"——这是 simplicity 收益 > 重启后重建几百毫秒的代价。
  目录 `config.KNOWLEDGE_DIR`（`data/knowledge/`，gitignore）；文件名清洗 + `resolve().parent`
  双防路径穿越；只吃 `.txt/.md`、2MB 上限；`chunk_text(500 字 / 90 字重叠)` 段落优先，避免概念被切半截。
- **反馈闭环只做「人挑出来喂回模型」的样本与偏好对，不自动训练**：双门槛（`selected` + `rating>=4`）
  产出模仿样本；偏好对取台账采纳版 vs 模型原文（`SequenceMatcher`），
  `PAIR_MATCH_FLOOR=0.1` **只随 meta、不判质量**——相似度低也可能是"用户改得更好"。
  内容 sha1 去重**倒序保留最近一条**（踩过坑：旧会话占着去重键会让新样本凭空消失）。导出 JSONL，**0 API 消耗**。
- **3+2 布局取代 v1.2.1 的「五列一屏」**：`.columns` 两行（上 3 下 2）、列宽自适应、行内 `overflow-y:auto`。
  动机是把"最后两路要滚很远"变短；代价是竖向整体变高——
  ⚠️ **体检实测：1366×768 下「引用核验」面板落在 635–905，超出视口 137px；1440×900 也差 5px（临界）**
  （v1.2.1 五列一屏时它底边 704，在首屏内）。**v1.4.0 把 v1.3.0 刚做成自动化的核验挤下了首屏。**
  **修（用户拍板后当轮落地）**：面板改 `position:sticky; bottom:0` 粘底常驻，且**明细默认收起**
  —— 一句常驻结论（已核验 / 存疑 / 未核验）+「展开明细」。
  为什么必须收起：整块 269px 贴底会把第二行参谋（论证策略师 / 风险提示员）**整排**压住，
  那就拿核验去堵参谋，本末倒置。收起后 93px，仍压住第二行约 125px（如实记在 HANDOVER §13）。
- **输入持久化边界放宽**：原定 `liveStateStore` 只存输入与 sessionId（产出可重算，台账才是事实来源），
  代价是刷新归零要重花 5 次上游调用。**修**：产出 + 整轮耗时一并落本地存储；恢复时按
  "status 是字符串"筛一遍再回填，认不出的路空着（重跑即可），写入端 1.2MB 上限、超出退回"只存输入"。

**体检结果**　pytest **302 passed**（非沙箱前台；v1.3.1 是 263）、`tsc --noEmit` 0 错误、
`vite build` 成功（41 模块 / JS 184.50 kB）；CSRF 四态真打实测通过；mavis 接触面仍只有
`mavis_bridge.py`；mock 上游端到端 0 消耗跑通一轮，3+2 渲染与自动核验均正常、无 JS 异常。

**续：协议桥跨站可烧额度（同轮追加，用户拍板后修）**　`main.py` 把 `/bridge` 整条豁免在
`csrf_guard` 之外（mavis 是服务端进程，发不出 UI 头），原先指望"只监听本机 + 凭据不落盘"
兜底。实测这条兜底不成立：桥转发前不看任何来源，而浏览器 `text/plain` POST 是 CORS 简单
请求（不发预检、也发不出自定义头），跨站 POST 能带着 `x-api-key` 打到上游 —— 即跨站成本放大。
→ 桥内补来源校验：无来源放行（mavis / curl 的自然形态），跨站 403 且**在碰上游之前**就拒；
白名单 = `127.0.0.1` / `localhost` / `::1` + 本地 dev 源。**纵深防御口径**：豁免前缀不该等于
"零校验"，桥必须自己再判一层来源。回归手段 `scripts/bridge_probe.py`（0 消耗，可直接重跑）
与 `tests/test_bridge_origin.py`。
**另一条教训**：`/api/upstream` 只在 `kind == "anthropic"` 时写 `llm_bridge.CFG`，
切上游会不会连桥一起改完全取决于 kind —— 排查"桥到底指哪"要看 `/bridge/healthz`，别看
`/api/health`。
UX 清单里**只剩 UX-1（成本不透明）未做**。
