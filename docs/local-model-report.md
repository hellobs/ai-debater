# 本地模型（Ollama）接入实测报告

**——零成本开发与回归通道的可行性与能力边界**

| 项 | 内容 |
|---|---|
| 日期 | 2026-09-30 |
| 环境 | Windows 本机 · Ollama（本地推理） |
| 受测模型 | `qwen3:4b-instruct-2507-q4_K_M`（2.5GB） · `qwen3:8b`（5.2GB） |
| 目的 | 打通"零 API 消耗"的开发与回归通道，使改动可免费迭代 |
| 结论 | 链路可用且**零代码改动**。4B 在**逻辑审计员**一路上系统性失效；**8B 修复了这一路**（同一批谬误案例全部识别，见 §9），但五路并行耗时涨到约 5 倍，默认 20s 预算下 3–4 路会超时 ⇒ 本地路线宜定位为**离线 / 备赛通道**，现场仍须云端 |

---

## 摘要

本项目需要一条不产生费用的验证通道，以支撑 prompt / schema 的频繁迭代。本文检验将框架直连本机
Ollama 的方案。结果表明：因框架的 `OpenAIProvider` 与 Ollama 的 OpenAI 兼容端点协议一致，
接入**不需要任何源码改动**，且协议桥在此模式下不参与；结构化输出依赖的
`response_format: json_schema` 由 Ollama 原生支持。延迟方面，五路并行总墙钟约 9.74s
（约为云端方案的 7 倍），仍在默认预算内。

质量方面出现过**明确的失效边界**：4B 模型在**逻辑审计员**一路上对教科书级谬误连续返回空列表，
属能力下限而非链路缺陷。

**该边界已于 2026-09-30 用 8B 复测并被跨越**（详见 §9）：同一批谬误案例在 8B 下全部识别，
延迟约 5 倍。故"本地模型做不了逻辑审计"的说法**只对 4B 成立**，本文 §7 的用途边界已按此更新。

**关键词**：本地推理；零成本；结构化输出；能力边界；失败模式识别

---

## 1. 方法：接入方式（零代码改动）

框架的 `OpenAIProvider` 本即采用 OpenAI 协议，而 Ollama 提供 OpenAI 兼容端点，
故仅需将 `LLM_BRIDGE_URL` 由协议桥改指 Ollama：

```bash
export LLM_BRIDGE_URL=http://127.0.0.1:11434/v1
export LLM_MODEL=qwen3:4b-instruct-2507-q4_K_M
```

`backend/app/config.py` 的 `LLM_BRIDGE_URL` / `LLM_MODEL` 均读环境变量，
`mavis_bridge.py` 将其作为 `base_url` 传入 `create_llm_provider` —— **不需要修改任何源码**。

已封装为脚本：`bash scripts/run_local.sh`（内含 Ollama 探活与并发预设）。

> **此模式下协议桥（:8011）不参与。** 桥的职责是翻译 Anthropic 协议并修复 JSON 形状；
> 而 Ollama 的 OpenAI 端点原生支持 `response_format=json_schema`（实测见 §2），两项职责均不再需要。
>
> 附带提示：本机 curl 访问 `127.0.0.1` 会被系统代理拦截为 `os error 10061`，
> 探活与调试本地端口须一律加 `--noproxy '*'`。

## 2. 结果（一）：结构化输出

框架的结构化输出**依赖** `response_format: json_schema`。实测 Ollama 完整支持：

```
POST /v1/chat/completions
  response_format = {"type":"json_schema","json_schema":{"name":"AuditorOut","schema":<pydantic schema>}}

→ {"res": []}            # 严格 JSON，顶层带 res —— 正是框架所需的形状
```

作为对照：协议桥之所以必须执行"将 schema 写入系统提示 + 修复 JSON 形状"，
原因是 **Anthropic 协议不含 `response_format` 字段**。改接 Ollama 时该上游约束不存在，问题自然消解。

---

## 3. 结果（二）：延迟（五路并行，热态）

首次调用为 15.68s（含模型加载），其后进入热态。下表为模型加载完成后的连续两次采样之一：

| 参谋 | 延迟 | 状态 |
|---|---|---|
| 质询手 | 1.19s | ok |
| 逻辑审计员 | 1.43s | **empty** |
| 解释方法策略师 | 4.15s | ok |
| 反驳手 | 7.77s | ok |
| 风险提示员 | 9.72s | ok |
| **总墙钟** | **9.74s** | = 最慢一路 |

- 总耗时 ≈ 最慢一路 ⇒ **确为真并行**，未被 `LLM_CONCURRENCY` 阻塞
  （前几路在 1–4s 内完成并释放信号量，最慢一路早已占位）。
- 对照云端（见 [`spike-0-report.md`](spike-0-report.md)）：deepseek-chat 三路并行 1.34s。
  本地 4B 约慢 7 倍，但**成本为零**，且仍处于默认 20s 预算之内。

## 4. 结果（三）：输出质量

| 参谋 | 判定 | 具体表现 |
|---|---|---|
| 反驳手 | 🟡 结构正确、引用可疑 | 产出 2 条完整涵摄三段式；但所引《著作权法》第 11 / 12 条**内容与真实法条不符**，且**未按指令标注「待核验」** |
| 质询手 | ✅ 可用 | 3 个问题，可直接抛出 |
| 逻辑审计员 | ❌ **失效** | 连续 3 次返回 `{"res": []}`，详见 §5 |
| 解释方法策略师 | ✅ 可用 | 正确识别「对方采用文义解释 → 我方应主张目的解释优先」 |
| 风险提示员 | ✅ 可用 | 3 条风险，分类（我方薄弱 / 法源不稳 / 事实不清）准确 |

**引用核验**：`《著作权法》第11条`、`第12条` 均判 `unverified`（`retriever: null`），
原因是 `data/corpus/` 尚为空。**这恰好说明引用核验的价值**：
模型编造法条内容时，唯有程序化核对能够拦截；模型自身的「待核验」自觉并不可靠。

## 5. 结果（四）：审计员失效的证据

以下两个用例直接以 Ollama 带 schema 调用，观测**模型原始输出**（排除解析环节的干扰）：

| 用例 | 对方发言 | 模型原始输出 |
|---|---|---|
| 案例 1 | 「著作权法只保护自然人的智力成果，AI 不是人，所以 AI 生成内容不应享有著作权。」 | `{"res": []}` |
| 案例 2 | 「隔壁老王用 AI 写了本书结果没人买，可见 AI 创作没有价值，所以所有 AI 生成物都不配受保护。」 | `{"res": []}` |

案例 2 属教科书级的**以偏概全 + 滑坡**（个例 → 全称否定；销量 → 权利资格），
4B 模型仍返回空列表。

**定性**

- 非代码缺陷 —— 链路、schema、解析均正常（`[mavis 链路] 返回类型=list 内容=0`，与模型输出一致）。
- 亦非被"宁可空列表"的纪律所抑制的保守 —— 该模型连明显谬误亦未识别。
- **属 4B 模型在"识别逻辑谬误"这一任务上的能力下限。**
  对照 [`spike-0-report.md`](spike-0-report.md)：deepseek-chat 在同一任务上能准确指认「偷换概念」。

> ⚠️ **样本量限制**：2 个用例 × 单次采样，不足以构成严谨评估（温度非 0）。
> 但"连续多次返回完全空"这一方向性信号足够明确，不宜带病投入现场使用。

## 6. 讨论：并发数的正确理解（修正一处此前判断）

此前曾记录一条判断：「`LLM_CONCURRENCY` 默认 4 < 5 路，是真缺陷」。本次实测后须**修正**：

- 框架的 `_GLOBAL_SEM` 为**进程级**信号量，确实会将并发压至 4。
- **但对本地 Ollama 而言，压低并发是正确的**：单实例推理下，并发超出只会排队，且争抢显存
  （框架源码注释原文：「Ollama 单实例并发有限，超了只会排队无收益」）。
  `scripts/run_local.sh` 因此将本地并发预设为 **2**。
- **仅当接入云端网关时**，才应将 `LLM_CONCURRENCY` 提升至 ≥ 参谋路数，
  否则第 5 路须等待第一批释放，总耗时翻倍。

⇒ 结论：这**不是"改一个数字"的缺陷**，而是**两种上游需要两套预设**。已分别固化于脚本与文档。

## 7. 结论：建议的用途边界

| 用途 | 4B（2.5GB） | 8B（5.2GB） |
|---|---|---|
| 链路自检、端到端回归、前端联调 | ✅ 完全够用，且零成本 | ✅ 够用，但一轮要等约 50s |
| 修改 prompt / schema 后的快速验证 | ✅ 够用（结构可验证，质量不可信） | ✅ 更好（**质量也可参考**） |
| 评估「改动是否更好」 | 🟡 仅能看结构与延迟，**质量判断仍须云端模型** | 🟡 质量可作参考，但仍不足以替代云端盲评 |
| 逻辑审计员这一路 | ❌ **系统性失效**（教科书级谬误也返回空） | ✅ **已修复**，见 §9 |
| 现场实战（默认 20s 预算） | ❌ 不可行（审计员失效） | ❌ 不可行（**3–4 路会超时**） |
| 离线 / 备赛（预算放宽到 120s 以上） | ✅ | ✅ **推荐**，质量明显优于 4B |

> 一句话：**本地路线解决"不花钱也能迭代"，不解决"现场快"。** 现场那 20 秒仍然只有云端模型给得起。

## 9. 8B 复测（2026-09-30）：审计员失效被修复，代价是 5 倍延迟

换模型不需要动任何代码 —— 仍是 `LLM_BRIDGE_URL` 直指 Ollama、`LLM_MODEL` 换名即可（见 §1）。

```bash
OLLAMA_MODEL=qwen3:8b bash scripts/run_local.sh
```

### 9.1 逻辑审计员：同一批谬误案例，从"全漏"到"全中"

输入与 §5 逐字相同，走完整链路（`/api/analyze`），非绕过渲染层直接调模型。

| 案例 | 对方发言节选 | 4B（§5 记录） | 8B 本次 |
|---|---|---|---|
| 1 | 「著作权法只保护自然人的智力成果，AI 不是人，所以 AI 生成内容不应享有著作权。」 | `{"res": []}` | **2 处**：偷换概念、稻草人 |
| 2 | 「隔壁老王用 AI 写了本书结果没人买，可见 AI 创作没有价值……」 | `{"res": []}` | **2 处**：以偏概全、偷换概念 |

8B 的判定不止"发现得出来"，引用也切得准 —— 例如把「将'自然人'等同于'人类'，忽略法律中可能
存在的法人主体」标为偷换概念，把「AI 不是人所以不享有著作权」单独标为稻草人。
单路耗时 14.09s / 7.41s（热态），对比 4B 的 1.43s。

### 9.2 五路并行：慢约 5 倍，默认预算会大面积超时

同辩题、同名册（默认五路）、`LLM_CONCURRENCY=2`，预算先放宽到 300s 量真实耗时：

| 参谋 | 第 1 次 | 第 2 次（热态） |
|---|---|---|
| 反驳手 | 11.11s | 10.55s |
| 质询手 | 18.17s | 32.79s |
| 逻辑审计员 | 26.14s | 41.47s |
| 论证策略师 | 38.29s | 25.42s |
| 风险提示员 | 51.79s **empty** | 48.42s **empty** |
| **总墙钟** | **51.81s** | **48.43s** |

对照 §3：4B 五路总墙钟 **9.74s** ⇒ **8B 约慢 5 倍**。
**超过默认 20s 预算的路数：第 1 次 3/5，第 2 次 4/5。**

这就是新结论的由来：**8B 把质量补上了，把"现场 20 秒"挤掉了。**
若要真的用它，得把时间预算放宽（ADVISOR_BUDGET_S 或界面上的预算下拉），当作离线通道。

### 9.3 一个未查明的问题：并发下风险提示员会返回空

上表中风险提示员两次都是 `empty`。隔离验证（临时名册只开它、`LLM_CONCURRENCY=1`）的结果是：

```
status : ok   耗时 9.7s
对方可能诱导我方承认 AI 生成内容无人类智力投入  ……（对方陷阱）
现行著作权法未明确 AI 主体资格，存在法源空缺     ……（法源不稳）
AI 生成内容是否包含人类智力成果尚无权威界定      ……（事实不清）
```

即：**单独跑，它 9.7 秒产出三条可用建议；并入五路并发，它总是空。**
⇒ 不是能力问题。怀疑与本机的显存 / Ollama 单实例排队有关，但**没有做二分验证、没有证据**，
此处只如实记录，不写成因。**实践含义：本地模式下别指望五路齐出**，宁可减少路数或串行跑。
